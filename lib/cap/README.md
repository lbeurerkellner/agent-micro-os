# 🧢 `cap` - Capability-Based CLIs

`cap` is a tool to create capability-bound CLI tools that couple API access to constrained, pre-defined behaviors. Secrets are stored via system keychain, and only made available to a previously approved version of a CLI according to a code and capability hash. 

`cap` supports Python, Node.js and shell programs, including dependencies installed via PyPI and npm, and program capabilities (file and network access) are specified by a simple configuration frontmatter in the respective code file. 

Overall, this makes `cap` CLIs ideal for use by AI agents, who you may not want to trust with full access to critical systems, such as cloud infrastructure, databases, or sensitive files, but want to provide with very specific, capability-based access, that can also be audited. To enable this, `cap` allows you to safely encapsulate a subset of capabilities behind approved CLIs, without requiring providers to implement fine-grained API access controls.

Since `cap` CLIs run isolated as containers, they can also be used to run untrusted code generated by LLMs, where network and file access policies constrain the code's behavior from the outside, according to least-privilege principles. This makes it suitable for self-modifying agents, while keeping the user in the loop when it comes to granting capability-based access to their access credentials, whenever a CLI implementation or capability changes.

## Quick Start

```bash
uv tool install --editable .
```

To test, see `examples/shell.cap.py`:

```
#!/usr/bin/env cap
# ---
# name: shell
# description: Interactive bash shell for testing network restrictions.
# dependencies: []
# network: "*"
# access: ['$@']
# ---
import os
os.execvp("bash", ["bash"])
```

This configuration gives full network access to a containerized `bash` process, and grants access to just the passed file path.

For instance, in the following, the shell CLI can only access and edit the `README.md` file:

```bash
> cap examples/shell.cap.py README.md

root@b5d85df70865:/workspace > echo 'testing' >> README.md

root@b5d85df70865:/workspace > curl google.com
(... google.com response ...)

root@b5d85df70865:/workspace > exit
exit


File Changes:
  ~ README.md

Network connections:
  google.com  GET  (2 req)
```

The `cap` tool also allows you to run the shell command in an audited fashion, constrained by pre-defined capabilities. In this example, the shell has the capability to read and write only `README.md` and to make arbitrary HTTP requests. Upon completion, the changes to `README.md` are reported and written back to the host file system, and all network connections made are also reported.
